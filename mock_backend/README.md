# Mock PMS Backend

A mock backend simulating a hotel's Property Management System (PMS) for the
**AI voice receptionist** proof of concept. It exposes the webhook endpoints that an
ElevenLabs Conversational AI agent (named "Anna") calls as tools during a guest conversation.

The project is a demo for the **Uzdrowisko Bukowy Dwór** health resort in Krynica-Zdrój, Poland.

> **Synthetic data.** All hotel, treatment, room and guest data is fictional and exists only
> for demonstration. No real PMS is connected and no bookings are stored.

## Features

- Five POST webhook endpoints (SPA availability, booking, cancellation, rescheduling,
  room availability, SMS summary, simulated human handoff).
- Interactive API documentation generated by FastAPI (Swagger UI and ReDoc).
- Console logging of every tool call, so the agent's actions are visible during a live demo.
- Optional Telegram notifications for summaries and handoff alerts.

## Requirements

- Python 3.10+
- Dependencies listed in `requirements.txt`

```bash
cd mock_backend
pip install -r requirements.txt
```

## Running the server

### Option A: start script (backend + public tunnel)

`tunnel/start_anna.sh` starts the backend, opens a Cloudflare tunnel, and updates the
ElevenLabs agent's webhook URLs automatically.

```bash
cd mock_backend/tunnel
./start_anna.sh          # default port 8011
./start_anna.sh 8012     # optional: custom port
```

### Option B: run directly with uvicorn

```bash
cd mock_backend
uvicorn main:app --reload --port 8011
```

Once running:

| Resource                | URL                             |
|-------------------------|---------------------------------|
| Server                  | http://localhost:8011           |
| Swagger UI              | http://localhost:8011/docs      |
| ReDoc                   | http://localhost:8011/redoc     |
| Health check            | `GET http://localhost:8011/`    |

> Port 8000 is often used by other system processes on Windows, so the default port is 8011.

## API endpoints

All endpoints accept and return JSON. Request examples below assume the server runs on port 8011.

| Method | Endpoint                          | Purpose                                              |
|--------|-----------------------------------|------------------------------------------------------|
| GET    | `/`                               | Health check, lists the available endpoints          |
| POST   | `/check_spa_availability`         | Free SPA time slots for a treatment on a given day   |
| POST   | `/book_spa_appointment`           | Book an SPA treatment and get a confirmation ID      |
| POST   | `/cancel_spa_appointment`         | Cancel a booking and apply the cancellation fee rule |
| POST   | `/reschedule_spa_appointment`     | Move a booking to a new date and time                |
| POST   | `/check_room_availability`        | Check room availability and calculate the stay price |
| POST   | `/send_sms_summary`               | Send a booking summary (console and/or Telegram)     |
| POST   | `/transfer_to_simulated_handoff`  | Simulate handing the call over to a human            |

### 1. Check SPA availability

```bash
curl -X POST http://localhost:8011/check_spa_availability \
  -H "Content-Type: application/json" \
  -d '{"service_name": "masaż klasyczny", "date": "2026-08-25"}'
```

```json
{
  "available": true,
  "slots": ["10:00", "11:00", "14:00", "14:30", "15:00", "16:00"],
  "service_name": "masaż klasyczny",
  "date": "2026-08-25"
}
```

### 2. Book an SPA treatment

```bash
curl -X POST http://localhost:8011/book_spa_appointment \
  -H "Content-Type: application/json" \
  -d '{"service_name": "kąpiel borowinowa", "date": "2026-08-25", "time": "14:00", "guest_name": "Jan Kowalski"}'
```

```json
{
  "success": true,
  "confirmation_id": "SPA-4821",
  "service_name": "kąpiel borowinowa",
  "date": "2026-08-25",
  "time": "14:00",
  "guest_name": "Jan Kowalski",
  "message": "Rezerwacja potwierdzona."
}
```

### 3. Cancel an SPA booking

Cancellation rules: more than 2 hours before the appointment is free of charge. Less than 2 hours
before, a 50% fee applies unless `medical_release` is `true`, in which case there is no fee.

```bash
curl -X POST http://localhost:8011/cancel_spa_appointment \
  -H "Content-Type: application/json" \
  -d '{"confirmation_id": "SPA-4821", "reason": "change of plans", "medical_release": false, "language": "en"}'
```

### 4. Reschedule an SPA booking

```bash
curl -X POST http://localhost:8011/reschedule_spa_appointment \
  -H "Content-Type: application/json" \
  -d '{"confirmation_id": "SPA-4821", "service_name": "masaż klasyczny", "new_date": "2026-08-26", "new_time": "10:00", "guest_name": "Jan Kowalski", "language": "en"}'
```

### 5. Check room availability

Room types: `jednoosobowy` (350 PLN/night), `dwuosobowy` (500 PLN/night), `apartament` (750 PLN/night).
Dates must be in `YYYY-MM-DD` format and the check-out date must be after check-in.
The weekend of 30-31 August 2026 is always fully booked, so any stay that includes those nights returns `"available": false`.

```bash
curl -X POST http://localhost:8011/check_room_availability \
  -H "Content-Type: application/json" \
  -d '{"room_type": "dwuosobowy", "check_in": "2026-08-25", "check_out": "2026-08-28"}'
```

```json
{
  "available": true,
  "room_type": "dwuosobowy",
  "price_per_night": 500,
  "check_in": "2026-08-25",
  "check_out": "2026-08-28",
  "total_nights": 3,
  "total_price": 1500,
  "message": "Pokój dostępny. Cena: 1500 PLN za 3 noc(y)."
}
```

Blocked-period example:

```bash
curl -X POST http://localhost:8011/check_room_availability \
  -H "Content-Type: application/json" \
  -d '{"room_type": "apartament", "check_in": "2026-08-30", "check_out": "2026-09-01"}'
```

### 6. Send an SMS summary

```bash
curl -X POST http://localhost:8011/send_sms_summary \
  -H "Content-Type: application/json" \
  -d '{"phone_number": "+48123456789", "summary_text": "Bukowy Dwór: SPA treatment confirmed for 25.08.2026 at 14:00. Ref: SPA-4821.", "confirmation_id": "SPA-4821", "language": "en"}'
```

The message is printed to the server console. If Telegram is configured, it is also sent to the
configured chat.

### 7. Simulated handoff to a human

Used instead of a native phone transfer, which requires SIP telephony. The event is logged to the
console and, if configured, an alert is sent to Telegram.

Departments: `recepcja` (main reception), `dyzurka_medyczna` (medical duty room).

```bash
curl -X POST http://localhost:8011/transfer_to_simulated_handoff \
  -H "Content-Type: application/json" \
  -d '{"department": "recepcja", "reason": "Guest asks for a human", "guest_name": "Jan Kowalski", "language": "en"}'
```

## Language

Endpoints accept a `language` field (`pl` or `en`, default `pl`). Responses carry English messages
when `en` is selected. Some guest-facing messages are returned in Polish by default, because the
voice agent reads them out to Polish-speaking guests.

## Telegram notifications (optional)

Telegram is optional. If the variables are not set, messages are printed to the server console only.
This is useful for demos, because the console shows each tool call in real time.

| Variable             | Description                                         |
|----------------------|-----------------------------------------------------|
| `TELEGRAM_BOT_TOKEN` | Bot token from [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID`   | Target chat or channel ID (often negative for groups) |

```bash
# Linux / macOS
export TELEGRAM_BOT_TOKEN="<your-bot-token>"
export TELEGRAM_CHAT_ID="<your-chat-id>"
uvicorn main:app --reload --port 8011

# Windows (PowerShell)
$env:TELEGRAM_BOT_TOKEN = "<your-bot-token>"
$env:TELEGRAM_CHAT_ID   = "<your-chat-id>"
uvicorn main:app --reload --port 8011
```

To find the chat ID, add the bot to the chat, send a test message, then open
`https://api.telegram.org/bot<TOKEN>/getUpdates` and read `chat.id`.

Do not commit real tokens. See `.env.example` for the variable names.

## Connecting the ElevenLabs agent

In the ElevenLabs agent configuration, set each webhook tool's URL to your public backend URL
(for example, the tunnel URL from `start_anna.sh`) followed by the endpoint path:

| Tool                            | Webhook URL                                              | Method |
|---------------------------------|----------------------------------------------------------|--------|
| check_spa_availability          | `<BASE_URL>/check_spa_availability`                      | POST   |
| book_spa_appointment            | `<BASE_URL>/book_spa_appointment`                        | POST   |
| check_room_availability         | `<BASE_URL>/check_room_availability`                     | POST   |
| send_sms_summary                | `<BASE_URL>/send_sms_summary`                            | POST   |
| transfer_to_simulated_handoff   | `<BASE_URL>/transfer_to_simulated_handoff`               | POST   |

For local testing, `<BASE_URL>` is `http://localhost:8011`. The external agent needs a public URL,
which the tunnel script provides.
